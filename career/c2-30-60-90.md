## Phase 0 — Before joining

### Goal

Arrive with a working mental model of TCS BFSI AI, not just generic AI knowledge.

### Build before Day 1

- [ ] understand [[bfsi/domain-map|BFSI value chains]]
- [ ] deep dive [[bfsi/risk-compliance-ai|risk & compliance AI]]
- [ ] understand public [[tcs/tcs-bfsi-ai-offerings|TCS BFSI AI offerings]]
- [ ] build [[ai/agentic-ai-bfsi-architecture|agentic BFSI reference architecture]]
- [ ] implement one safe public-data demo
- [ ] prepare a one-page evaluation framework
- [ ] prepare a one-page AI governance/control checklist
- [ ] follow [[dashboards/tcs-bfsi-ai-radar|TCS/BFSI AI signals]] weekly

### Recommended public-data demo

**Regulatory Change Impact Agent**

Input: public SEBI/RBI/IRDAI circular or consultation paper.

Output:

1. obligation extraction
2. affected process
3. affected system/control
4. engineering implication
5. evidence/source citation
6. human-review queue
7. confidence/evaluation result

This is safe to build publicly and directly relevant to regulated enterprise AI.

## Days 1–30 — Discover and become reliable

### Outcomes

- understand team charter and solution boundaries
- map stakeholders and dependencies
- understand current accelerators and platforms
- identify one recurring pain point
- establish reputation for clear execution

### Questions to resolve

- What business problems does the team repeatedly solve?
- Which AI assets are reusable today?
- What is the standard architecture/eval/observability stack?
- What usually blocks PoC → production?
- Which artifacts are repeatedly recreated?
- How is domain knowledge encoded today?

### Deliverables

- personal domain/process map
- architecture map of the current solution landscape
- glossary of team/client terminology
- one useful reusable checklist or template

Do not attempt a large reinvention during the first weeks. Learn the existing system first.

---

## Days 31–60 — Own a narrow leverage point

### Goal

Solve one repeated engineering or domain problem better than before.

Candidates:

- evaluation harness for agent workflows
- reusable observability/tracing template
- prompt/tool security test pack
- domain ontology/context pattern
- regulatory evidence template
- cost/latency benchmark harness

### Success criteria

Another engineer or solution team should be able to reuse the artifact without you explaining every step.

---

## Days 61–90 — Convert contribution into recognized leverage

### Goal

Move from contributor to someone associated with a useful capability.

### Deliverables

- production-quality reusable component or accelerator
- measured before/after impact
- concise architecture + operating guide
- internal knowledge-sharing session if appropriate
- backlog of next improvements based on usage feedback

## Reputation to build

Be known for:

- understanding the BFSI process before proposing AI
- making AI production-ready, measurable and controllable
- simplifying ambiguous architecture
- creating reusable engineering assets
- making teammates faster
